# 代码评审

按下面的流程做代码评审，**不要**跳过任何一步。

## 1. 定位范围

先确认要评审的文件：

- 用户没指明文件时，用 `search_code` 找出最近改动的相关代码；
- 用 `git_diff` 看本次改动（比通读整个仓库更有效）；
- 用 `ast_inspect` 看清类与函数的结构，别凭文件名猜。

## 2. 逐项检查

对每一处改动，按下面清单过一遍：

| 维度 | 看什么 |
|------|--------|
| 正确性 | 边界条件、空值、异常路径、并发竞态 |
| 安全 | 注入、越权、敏感信息硬编码、路径穿越 |
| 性能 | N+1 查询、无界循环、重复 IO、缺索引 |
| 可维护性 | 命名、重复代码、函数过长、隐式副作用 |
| 测试 | 关键分支有没有覆盖，断言是否有效 |

## 3. 输出格式

每条问题写成四行，不要写成一大段：

```
[严重级别] 文件:行号 —— 一句话说明问题
影响：…
建议：…（给出具体改法，必要时附代码片段）
```

严重级别只用三个：`严重`（会导致故障或数据损坏）、`一般`（能修但不急）、`提示`（风格建议）。

**没有发现问题时明确说"未发现问题"**，不要为了凑数编造问题。
